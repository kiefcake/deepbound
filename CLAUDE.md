# Deepbound — working notes for Claude

First-person 1-4 player co-op dungeon crawler. Unity **6000.3.23f1**, **URP**, **Netcode for GameObjects 2.13**
(UnityTransport for LAN/VPN/tests; Steam P2P transport + lobbies since 2026-10-26). Design source of truth: `docs/DESIGN_DOC.md` (its top table lists the
design decisions Claude made on the user's behalf).

The user wants autonomous progress: make the call, record it, keep going. They play-test builds themselves.

**Also read `docs/CAMP_AUDIT.md` (open camp items) and the CURRENT section of `docs/BOT_FINDINGS.md` (regenerate with `python tools/bot_digest.py` after any bot run) and act on them.** **Start every session by reading `docs/AGENT_PROMPT.md`** (the standing prompt: the loop, hard rules, backlog) and follow it.

**Production rules** live in `docs/PRODUCTION.md` (readability, teach-by-play tips, feedback, counterplay, accessibility options, performance budget, test-before-ship). New features follow them: a telegraph or tag for every threat, a `UI/Tips` entry for every new mechanic, a smoke check, lights under the level root (`Art/LightBudget`). Use `Art.ViewCamera.Current`, never `Camera.main` (the player camera is not tagged MainCamera).

## Build, run, test

Player builds are **release** by default since 2026-10-17 (faster, no "Development Build" stamp; logs still go to Player.log / `-logFile`). Set `DEEPBOUND_DEV=1` for a development build when you need stack traces with line numbers.

Everything is **generated by code** — textures, materials, meshes, prefabs, the scene. Never hand-edit
`Assets/Prefabs`, `Assets/Scenes`, `Assets/Resources/Materials` or `Assets/Art/Generated`: change the generator and
rebuild.

```
# Full build: bake art -> prefabs -> scene -> Windows player at Builds/Deepbound/Deepbound.exe
"/c/Program Files/Unity/Hub/Editor/6000.3.23f1/Editor/Unity.exe" -batchmode -quit -projectPath "$(pwd -W)" \
  -executeMethod Deepbound.EditorTools.GameBuilder.BuildWithPlayer -logFile Logs/game-build.log
grep -E "error CS|warning CS|Player build" Logs/game-build.log | grep -v PackageCache
```

- **If the user has the game open**, Windows locks the exe: set `DEEPBOUND_BUILD_PATH=Builds/DeepboundNext/Deepbound.exe`
  for the build, then `cp -rf Builds/DeepboundNext/. Builds/Deepbound/` once they close it. Check with
  `tasklist | grep -i deepbound`. Never kill their game to rebuild.
- **Smoke test** (headless, the main regression check; it waits on events, so it is robust to new checks; ~100 PASS lines on host, 12 on client, zero FAIL; the client waits until the host carries it back from a soul (or its 34 s run out) and then quits, so two-player checks (voice, rage, soul skull) go in the early "while the client is still connected" block, before the soul skull):
  ```
  cd Builds/Deepbound && L=$(cygpath -w "$PWD")
  ./Deepbound.exe -batchmode -nographics -port 7791 -host -smoketest 40 -logFile "$L\\host.log" & sleep 4
  ./Deepbound.exe -batchmode -nographics -port 7791 -client -smoketest 34 -logFile "$L\\client.log" & wait
  grep -E "FAIL|Exception" host.log client.log; grep -c PASS host.log client.log
  ```
  A watchdog quits with `FAIL watchdog` if the sequence throws — then read the exception above it.
- **Screenshots** (windowed, pops a window — only when the user is not playing):
  `Deepbound.exe -shots <dir> -screen-fullscreen 0 -screen-width 1280 -screen-height 720`. Captures title, class
  screen, lobby, floors 1-3, every newer enemy, chest, pause menu, run summary. Read the PNGs to judge visuals.
- **Boss test**: `-bosstest <dir>` drops the host into each boss arena and logs `[Boss]` mechanic lines.
- **Music check**: `-executeMethod Deepbound.EditorTools.GameBuilder.TestMusic` (batch editor).
- Commit after each verified chunk, with the attribution line the session specifies.

## How things work (the parts that are easy to get wrong)

- **Authority**: movement is owner-authoritative (NetworkTransform Owner mode); everything else — damage, loot,
  stats, AI — is server-only. Clients send intent via `[Rpc(SendTo.Server)]`; effects go out via
  `[Rpc(SendTo.ClientsAndHost)]`. The server cannot move a player; it asks the owner (`KnockbackReceiver`).
- **Floors are a seed**: `DungeonDirector.Floor` = (nonce/seed, depth); depth -1 is the lobby. Every peer rebuilds
  geometry locally; only the server bakes the navmesh and spawns networked things. `ArenaBuilt` fires on every
  rebuild; players re-place themselves on it.
- **Teams**: `Players`, `Enemies`, `Props`. Anything aimed at Enemies also hits Props (`CombatQuery.Matches`), but
  AI, radar, music and relic procs check `Team.Enemies` explicitly.
- **Damage pipeline**: `Health.ServerDamage` → DEF floor → `IncomingModifiers` in order (dodge i-frames are
  inserted first, then block, relics) → only health actually lost is reported (overkill is not damage).
- **Classes**: every kit is on the prefab; only the kit matching `PlayerProgress.ClassId` acts (`Active` check).
  Add a class = new kit implementing `IClassKit` + `ClassDefinition` entry + `CharacterArt` rig + view model +
  `ClassId` value (append only) + prefab component in `GameBuilder`.
- **Progression (no stat potions any more)**: the class weapon is never found; Embers temper it at the `Anvil`
  (start room, G opens the forge) +0..+5, each level +4 ATT +2 DEX. At +2 you pick one of two `WeaponPaths` per
  class (effects gated in kits by `progress.OnPath(n)` / `Mastered(n)` at +4). Sigils rank Q/E 1..3 at the anvil
  (`AbilityRanks`: `progress.Potency(slot)` x1.3 at rank 2, `CooldownFor(slot)` and `Twist(slot)` at rank 3).
  Gear (`GearDrop`) is rolled per player and only visible to its owner (`CheckObjectVisibility` + visual gate);
  F stows to the pack (since 2026-10-20), X scraps for embers at the anvil. Gear stats are derived from (id, quality, depth).
- **Edges and hones** (2026-10-23, "improve the progression"; tempering was an automatic buy and a full run sat on 500-700 embers and 2000 gold after +10): `Progression/Edges.cs`. At +5/+7/+9 (`Edges.Levels`) one of three edges is forged (`Edges.Offer(runSeed, clientId, slot, taken)`, seeded by `RunStartedAt` so client and server agree; `PlayerProgress.EdgeBits` one byte per slot, `ChooseEdgeRpc`/`ServerChooseEdge`, `OpenEdgeSlot` blocks tempering and `ServerFreeTemper` until chosen). ## Sharp edges already hit (do not rediscover)

0. `CombatQuery.Arc/Circle` return a fresh list per call: a hit can trigger another query (thorns, Bellringer's Hauberk) mid-loop; a shared static list threw "Collection was modified".

1. **One NetworkBehaviour/MonoBehaviour per file, file named after the class.** Otherwise Unity cannot serialise it
   onto a prefab and the prefab silently has no script (NullReference at spawn). Runtime-only `AddComponent`
   helpers (e.g. `MeteorFlash`, `HitFlash`) are exempt but keep the rule anyway.
2. **NetworkObject GlobalObjectIdHash** is 0 when `NetworkObject` is added from script; `GameBuilder` re-runs
   `OnValidate` via reflection after saving each prefab. Keep using `SavePrefab`.
3. **URP strips shader variants** no material asset uses — that is why materials are baked assets in
   `Resources/Materials`, never `new Material()` with keywords at runtime.
4. **Environment reflections** are turned down (`RenderSettings.reflectionIntensity = 0.12`): Unity's default sky
   made water look like ice and steel like chrome.
5. **Glow** is HDR emission; above ~2-3x it blows out to white under ACES + bloom. Keep flame/orb glow modest.
6. **Enum values are append-only** where synced or serialised (`StatType`, `LootKind`, `Relic`, `RunPhase`,
   `ClassId`, `SkeletonKind`, `ProjectileKind`, `RigAction`, `Team`).
7. **Esc ordering**: shop/class screen close first; `PauseMenu.OtherMenuOpenLastFrame` stops the same Esc pausing.
8. **No time-scale hitstop**: on a host it would slow the whole server. Use `ConfirmHit` camera kick.
9. **IMGUI view-model and RenderTexture aspect**: draw RTs with an aspect that matches their rect, or heads get
   cropped (the class-select previews hit this).
11. `MeshKit.Lathe` partial sweeps run from +Z toward +X (same sense as Unity yaw), so the gap spans [sweep, 360]. A hood/cowl/open helm faces its opening forward with yaw `180 - sweep/2`; a cloak/ribcage with its gap at the back uses `-sweep/2` (e.g. 170 -> 95). Every hood was built facing backward until 2026-10-16. Bosses never wear a pointed hood over a face (Tide Lich and Cardinal have theirs removed).
14. Perf with `-uncapped` (shots run flag: no VSync/frame cap whatever the player saved; the user's PC is an integrated AMD Radeon and their saved preset is Low), 2026-10-21 on Low: camp road 13 ms, start room 8.6, combat 8.7, boss room 11 (76-116 fps); menus cost more (pause 13, options 18, the guide 24-32, class select 15-23 with its full-res previews) from IMGUI text; the guide caches its measured page (`guideCacheKey`). Low/Medium (render scale 0.7/0.85) upscale with FSR 1 (`urp.upscalingFilter`, sharpness 0.75): visibly crisper at the same cost.
13. Performance (2026-10-17, `[PerfSample]` lines in shots.log = 90-frame means at camp road / start room / combat / boss room, with the top renderer names): there is no occlusion culling, so the player camera's far plane follows the fog (`2.6 / fogDensity`, 45-120 m; 220 at camp). Built characters, critters, torches, braziers and spike beds call `MeshKit.MergeParts`/`MergeRig` (leaf parts under one pivot with the same material, tint, glow and shadow mode become one mesh, owned by `Art/MergedMesh`); new multi-part props should do the same. Leaf parts with extra components are never merged; a merged renderer is named "Merged".
12. View-model point lights a few cm from the hand flood it white; weapon trails via `TrailRenderer` smear with camera turns in first person (use a view-space mesh like the Knight's `Slash`).
10. Python edit scripts: put non-ASCII text (·, —) in a `.py` file via Write, not a bash heredoc — heredoc input
    mangled the escapes once.
